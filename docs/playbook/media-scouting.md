# Media scouting: массовая скачка картинок/гифок/видео из поисковой выдачи

Проверенный рецепт (13.08.2026): по текстовому запросу получить пачку полноразмерных
картинок или коротких видео — как «что найдёт поисковик», так и «топ-N ровно в порядке
выдачи». Всё — без API-ключей и без sudo.

## TL;DR

| Задача | Инструмент |
|---|---|
| Много картинок пачкой | пакет `ddgs` → `DDGS().images()` |
| Топ-N в порядке, как видит человек | Playwright → duckduckgo.com → перефетч `i.js` |
| Видео (с фильтром по длительности) | `DDGS().videos()` → скачивание `yt-dlp` |
| Гифки | `DDGS().images(..., type_image="gif")` |
| Google Images | напрямую — никак (капча); только сниппет в живом браузере |

## Почему не Google

Google Images режет любой автоматический доступ капчей (HTTP 429 → `/sorry`):

- скраперы-библиотеки (icrawler и т.п.) — качают 0 файлов, гугловый парсер у них
  перманентно сломан;
- headless-браузер (Playwright) — капча сразу на первой странице, IP флагуется.

Единственный обход — живой браузер человека: открыть выдачу, проскроллить (ленивая
подгрузка!), в DevTools-консоли собрать полноразмерные URL из ссылок результатов:

```js
copy([...document.querySelectorAll('a[href*="/imgres?"]')]
  .map(a => new URL(a.href, location.origin).searchParams.get('imgurl'))
  .filter(Boolean).join('\n'))
```

Список из буфера дальше качается любым HTTP-клиентом. Порядок ссылок = порядок выдачи.

DuckDuckGo отдаёт практически тот же индекс (у него под капотом Bing), но ботов не
гоняет — поэтому всё ниже строится на нём.

## Картинки массово: `ddgs`

```python
from ddgs import DDGS

results = list(DDGS().images("запрос", max_results=100))
# у каждого результата: title, image (полноразмерный URL), thumbnail, width, height
```

Скачивание — обычный `requests`, но с обвязкой, иначе в папке будет мусор:

- User-Agent обязателен (без него половина сайтов отдаёт 403);
- расширение файла брать из `content-type` ответа (`image/jpeg` → `.jpg`, …),
  не из URL — URL часто врёт;
- отсев: не-image content-type и файлы < 5 KB (битые превью, заглушки);
- дедуп по sha1 содержимого — одна картинка приходит с разных зеркал;
- один запрос даёт ~30–40 результатов; для объёма — несколько вариантных
  формулировок запроса с дедупом поверх (4 варианта ≈ 130 уникальных файлов).

Гифки — то же самое с `type_image="gif"`.

Грабля: при частых запросах подряд ddgs ловит `DDGSException` (rate limit). Лечится
паузой либо переходом на браузерный путь (ниже) — он не лимитируется.

## Топ-N «как на странице»: Playwright + перефетч `i.js`

Порядок результатов у API и у веб-страницы DDG **разный** (проверено: топ-10 совпал
с UI только у браузерного пути). Если важно ранжирование («какие были в топ-10») —
только через браузер:

1. Открыть `https://duckduckgo.com/?q=<query>&iax=images&ia=images`.
2. Полноразмерных URL в DOM нет — плитки держат только bing-превью. Но страница уже
   сходила за JSON. Найти URL этого запроса:
   ```js
   performance.getEntriesByType('resource').map(e => e.name).find(n => n.includes('i.js'))
   ```
3. Перефетчить его `fetch`-ем **из контекста страницы** (там же токен vqd, куки —
   всё уже валидно) и распарсить: `results[].image` — полноразмерные URL строго в
   порядке страницы.
4. Скачать по списку, нумеруя файлы позицией (`top-00.jpg` = первое место).

Для видео всё то же, но endpoint называется `v.js`, а URL ролика лежит в
`results[].content`.

Ожидаемые потери: 1–2 из десятки не отдадутся (битый SSL, таймаут хостинга) — качать
с запасом индексов и добирать следующими позициями.

## Видео: поиск `ddgs` + скачивание `yt-dlp`

```python
results = list(DDGS().videos("запрос", max_results=40))
# duration ("2:18"), title, content (URL, в основном YouTube), publisher
```

`duration` парсится в секунды → фильтр «только короткие» делается на своей стороне
(у DDG-фильтра `duration="short"` гранулярность «до ~5 минут», не тоньше).
Эмпирика: новостных роликов короче 10 секунд практически не существует — коротышки
это 30–60-секундные шортсы; «хайлайты» короче — только резать самому ffmpeg-ом.

Скачивание:

```bash
yt-dlp -f 'bv*[height<=720]+ba/b[height<=720]/b' --no-playlist \
  -o '%(autonumber)02d - %(title).80s.%(ext)s' <url...>
```

Грабли yt-dlp, обе поймали на первом же прогоне:

- **Нужен ffmpeg.** YouTube отдаёт видео и звук раздельными потоками; без ffmpeg
  остаются несклеенные половинки `*.fXXX.mp4` + `*.fXXX.webm`. Без sudo ffmpeg
  ставится так: `pip install imageio-ffmpeg`, путь к статическому бинарю даёт
  `imageio_ffmpeg.get_ffmpeg_exe()`, скармливается через `--ffmpeg-location`.
- **HTTP 403 на части потоков.** Лечится повтором с другим клиентом плеера:
  `--extractor-args "youtube:player_client=default,android"`.

## Ограничения

- DDG ≈ Bing-индекс: совпадает с гуглом по содержимому процентов на 80, по порядку —
  нет. Для точного «гугл-топа» — только сниппет в живом браузере (выше).
- Выдача бывает разношёрстной: точный запрос даёт мало результатов, вариантные —
  тянут смежный шум. Релевантность топа проверять глазами, не доверять слепо.
- Provenance: источники и лицензии скачанного этот рецепт не решает — для
  публикуемого контента материал прогонять через обычные правила лицензирования
  проекта, скачанное из выдачи по умолчанию непригодно к публикации.
