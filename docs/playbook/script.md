# Сценарий: структура текста и фактология

Ролик — не абзац, прочитанный вслух. Сценарий состоит из **тактов (beats)**, привязанных
ко времени.

## Каноническая структура

```text
0s        хук

сразу:
обозначить субъект / контекст

дальше:
новая информация

дальше:
эскалация / нерешённый вопрос

дальше:
payoff

опционально:
второй твист

в конце:
мягкий CTA / брендинг
```

Хук — отдельная подсистема со своими правилами, см. `hooks.md`.

## Правило удержания

Зритель должен получать повод продолжить смотреть **каждые несколько секунд**. Механизмы
обновления внимания:

- новый факт,
- новый вопрос,
- смена картинки,
- схема / диаграмма,
- zoom или подсветка детали,
- противоречие,
- эскалация,
- эмоциональный сдвиг,
- анонс payoff'а.

## Запрет на padding

Нельзя добивать текст ради попадания в целевую длительность. Целевые длительности —
приоры, а не квота: `timing.md`.

## Фактология

Для фактических каналов галлюцинация убивает бренд. Сценарий производится цепочкой:

```text
idea
↓
source retrieval / research
↓
claim list
↓
source-backed outline
↓
script
↓
claim verification
```

URL/ID источников хранятся вместе с роликом:

```json
{
  "claims": [
    {
      "text": "...",
      "source": "https://...",
      "confidence": 0.93
    }
  ]
}
```

Массивная RAG-архитектура для v1 не нужна — обычного веб-ресёрча достаточно. RAG по
внутренней evergreen-базе добавляется позже.

## Чего сценарий делать не должен

- быть тривиальным парафразом другого ролика,
- держать шаблон, в котором меняются только имена собственные,
- нести ресёрч, не привязанный к конкретной теме.

Форматы повторяться могут, содержание — нет; полная формулировка ограничения —
`../product/content-factory-context.md`, §39.

Механики сторителлинга, под которые пишется текст, — `formats.md`.
