# 一般生活方式内容“质量优先简化模式”设计

## 背景与决策

`HB20260810` 及后续 `general_wellness_uncredentialed` 批次以一般生活方式观察为主，不对外声称医疗身份，不提供诊断、治疗、处方、药物剂量或疗效承诺。用户已明确选择“质量优先简化模式”：取消这类内容的外部双人审核、Ed25519 签名和多层人工状态门，把生产重心转回脚本、分镜、画面、视频、音频和四平台包装质量。

本设计不取消事实与平台安全边界，而是将它们改为自动、本地、非签名的轻量检查。检查失败时优先改写或降级表述，不要求用户反复补审核人、时间和密钥。

## 适用范围

简化模式只适用于：

- `content_profile = general_wellness_uncredentialed`；
- 中国大陆 35—60 岁普通用户的生活方式观察；
- 睡眠、进餐、日常活动、时点、环境和主观感受的记录；
- 不宣称专业医疗身份的视频号、抖音、小红书和快手内容。

不适用于：

- 疾病诊断、治疗方案、药物使用、剂量、停药或急救指导；
- 对检测数值作医学阈值解释、疾病判断或疗效归因；
- 以医生、护士、药师、营养师等专业身份出镜或背书的内容；
- 法律、平台或付费供应商明确要求具名授权的操作。

超出上述范围的内容不自动降级成“普通生活方式”后发布；应移出本模式，另行处理。

## 选定方案与未选方案

### 选定：按 profile 分流

使用现有 `general_wellness_uncredentialed` profile 作为唯一开关，不给当前不可变批次快照追加新字段，也不创建平行 manifest schema。普通生活方式 profile 走简化流；其他 profile 保持原审核合同。

优点是变更范围小、当前批次无需重建、不会将简化政策误用到真正的医疗内容。

### 未选：删除所有安全检查

该方案最快，但会让医疗化用语、虚构小程序能力、虚拟数据真实化、疗效承诺和平台禁词直接进入成品，与“顶级质量”目标冲突，因此不采用。

### 未选：每期人工分级审核

该方案更稳健，但仍会让日更流程反复暂停，不符合用户当前对生产效率的明确要求，因此不采用。

## 简化状态流

`general_wellness_uncredentialed` 使用下列流转：

1. `research_pending → production`：事实卡、公开题面、脚本、分镜、图文文案和四平台文案齐备，自动边界扫描通过。
2. `production → automated_qa_passed`：视频、音频、字幕、封面和图文经技术与内容 QA 通过。
3. `automated_qa_passed → ready_to_publish`：四平台包装完整，质量分与分项下限通过，输出仍为 `human_pending`。
4. 平台提交：用户手工完成，系统不自动登录或发布。

简化流不使用 `medical_review_pending`、`approved`、`final_qa_passed`，也不把自动 QA 伪装成真人审核。原有非普通生活方式 profile 的状态流不变。

## Manifest 兼容策略

- 保留现有 `medical_review` 与 `final_qa` 字段，避免破坏现有 manifest 结构。
- 当 profile 为 `general_wellness_uncredentialed` 时，两字段的 `status` 写为 `not_required`，审核人与时间保持空字符串，不伪造任何人工通过。
- `automated_qa` 是唯一内部门记录，必须从真实制品重算，不信任输入中自报的 `passed`。
- 公开包装不出现“医学审核”、“专家审核”或任何真假审核人姓名。

## 轻量自动安全扫描

扫描与制作同步执行，不设外部等待门，覆盖：

- 公开文案不含诊断、治疗、处方、药物剂量、停药、疗效保证、医疗身份或恐惧诱导；
- 来源、编辑推断和剧情设定分层，不把小样本、旧研究或相关性写成确定因果；
- 减重云、体脂秤和“健康卫士”只呈现已有截图或已确认能力；不宣称未证实的自动同步、诊断、提醒、远程点评或设备连接能力；
- 剧情数据、曲线和前端动画始终标注“剧情示例｜不作为诊断依据”，不与用户真实数据混用；
- 真实中文 UI 用后期贴屏，生成模型不重画可读界面。

当扫描失败时：

1. 能改写为生活方式观察的，在同一轮修复并重验；
2. 无法在不改变核心含义的情况下修复的，移出本 profile，不进入手动发布包；
3. 不请求用户提供外部审核签名来解锁一般生活方式制作。

## 视频质量主流程

### 脚本与节奏

- 首句必须在 S01 可用时长内自然说完；
- 逐镜中文局部语速不高于 3.9 汉字/秒；
- 一句对应一镜，动作、景别、镜头目的和叠字一致；
- 单条 Grok 动态源的一镜需求不超过 5.8 秒；不用慢放、循环或插帧掩盖素材不足。

### 分镜与图像

- 9:16、1080×1920，无模型生成文字、Logo、水印、纸、笔、本子和不必要的医疗信号；
- 人物身份、发型、服装、年龄、手指、物体数量和空间连续性逐镜检查；
- 手机需贴屏时保持约 2.0—2.2 的可见长宽比、四角完整和中央屏幕无遮挡；
- 原图与 25% 联系表都要审看，联系表不替代原图。

### Grok 手动生成与视频 QA

- 每镜一条中英双语提示词，相邻提示词恰好空一行；
- 只上传无字正式首帧，不上传带 UI 或带中文叠字的审阅图；
- 成片逐镜检查人物、手、物体、文字、界面、运动连续性、时长和角色还原；
- 中文 UI 和数据动画由确定性后期完成，不接受 Grok 重绘的乱码界面。

### 音频、剪辑和四平台包装

- 普通话自然语速，镜内字幕与旁白逐字对应，不为赶时长异常加速；
- 字幕安全区、音量、响度、峰值、转场和结束卡通过机械与人工目检；
- 视频号、抖音、小红书和快手分别优化标题、封面短句、正文和置顶互动，不用同一模板硬复制；
- 所有包仅为 `human_pending`，最终上传和发布由用户手工完成。

## 当前 Task 8 证据处理

## 错误处理与保护范围

- 不修改已有不可变批次快照、Task 6/7 正式图片哈希或已完成的内容文档；
- 状态变更仍经稳定 CLI 和原子 active/reference 事务执行，不手改 JSON 绕过一致性保护；
- 检测到旧 journal、lock、哈希不符、重解析点或目标已有异字节时仍失败关闭；
- 不触碰 cookie、token、密码、API key、私钥或任何平台凭证。

## 验证策略

实施必须先写失败测试，再做最小改动，覆盖：

1. 普通生活方式 profile 不再要求外部审核或签名；
2. 其他 profile 的原审核与签名门必须保持；
3. 一般生活方式的三步状态流可用，非法跳转仍拒绝；
4. `not_required` 不能被解释为 `approved`，公开包不能泄露内部审核字段；
5. 公开禁词、凭证字段、虚拟数据标签和减重云/设备能力边界仍失败关闭；
6. 质量总分仍至少 92，且各分项下限不变；
7. 旧 profile 回归、CLI 无输出污染、active/reference 事务、重构可复现性和整套测试通过；
8. Task 9 手动包只消费通过简化自动门的无字首帧和已锁分镜。

## 成功标准

- 当前十集不再等待姓名、时间、公钥或签名；
- 不伪造任何已审核回执；
- 自动事实/平台边界扫描与质量门可重现、有测试、有失败原因；
- 简化流不影响真正医疗内容的原门禁；
- 十集可直接进入 Grok 浏览器扩展手动包制作；
- 最终发布仍是用户手工操作，不包含自动发布能力。
