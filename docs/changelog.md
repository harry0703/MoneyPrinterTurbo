# Changelog

Запись на каждый бамп `version` в `pyproject.toml`. Формат — что и зачем поменялось,
со ссылками на решения в `architecture/decisions/`.

## Unreleased

- **Фото-вставки подбираются по смыслу, а не по алфавиту**: папка делится на темы
  (подпапка = тема, иначе первый нечисловой токен имени: `20-spider-01.jpg` → `spider`),
  LLM одним вызовом раскладывает **темы** по строкам сценария, конкретный файл внутри
  темы выдаёт код по порядку. Раньше LLM выбирал только «сильные строки», а фото
  раздавались им по сортировке имён — тема попадала под чужую фразу. Описания тем
  можно задать в `themes.json` рядом с фото. Фолбэк прежний: пустой план → выбор строк
  → равномерная раскладка. `architecture/photo-overlays.md`.
- **Фото-вставка больше не уезжает от своей фразы**: при пересечении карточка
  обрезается началом следующей, а не сдвигается за конец предыдущей (на плотной
  раскладке набегало до +9 сек дрейфа — фото приезжало через полтакта после строки,
  к которой подобрано). Вставки короче 1.0 сек выбрасываются.
- **Фото-карточки крупнее**: дефолт `photo_size` 0.42 → 0.63 (площадь ×2.25), потолок
  высоты для фото поднят с 0.45 до 0.62 высоты кадра (иначе портретные упирались в кап),
  боковой сдвиг ограничивается шириной карточки — крупная больше не вжимается в край.
- **Плотные фото-вставки**: `photo_amount` поднят до 40, добавлен `photo_duration`
  (деф. 2.0 сек ± 0.5 — прежнее поведение), CLI `--photo-duration`, слайдер в WebUI.
  При плотной раскладке карточки больше не наезжают друг на друга — старт сдвигается
  за конец предыдущей, потому что окна субтитров короче показа фото. Если файлов в
  папке больше, чем вставок, они берутся равномерно по всему списку, а не первые
  `amount` по алфавиту (раньше тема, отсортированная последней, молча выпадала).
  `architecture/photo-overlays.md`.
- **Субтитры без пословных таймингов больше не уплывают**: длительность фразы
  считается от **времени речи**, а не от общей длины (пауза перестала «произноситься»),
  и граница предложения притягивается к ближайшей реальной паузе в пределах 1.2 с.
  Замер на 55-секундной озвучке Gemini: границ, попавших в паузу, 4/31 → 16/31,
  средний промах 0.95 → 0.73 с. Внутрифразовые паузы (тире, вдох) в притягивании не
  участвуют — иначе строка прыгает раньше голоса.
- **`subtitle_max_chars`** (по умолчанию 0 — выключено): строки длиннее лимита
  дробятся по границам слов, тайминг делится пропорционально. Лечит субтитры на
  пол-экрана из одного длинного предложения.
- **Karaoke-подсветка** — `subtitle_highlight_mode = "keyword" | "karaoke"`
  (по умолчанию `keyword`, поведение не меняется). В режиме `karaoke` подсветка
  едет по словам, слот слова внутри фразы считается по числу букв —
  `architecture/subtitle-highlight.md`. CLI: `--subtitle-highlight-mode`.
- **Темп у Gemini TTS**: `voice_rate` для `gemini:*` голосов больше не игнорируется —
  применяется после генерации через `ffmpeg atempo` (питч не плывёт). Плюс два ключа
  конфига: `gemini_tts_style_prompt` — инструкция о подаче, которая уходит в запрос,
  но не произносится и не попадает в субтитры; `gemini_tts_max_pause_ms` — длинные
  паузы подрезаются до этого значения (0 — выключено), а `gemini_tts_pause_detect_ms`
  (деф. 500) задаёт, что вообще считается длинной паузой. Порог детекта отделён от
  порога речи в `_detect_speech_spans`: он меняет подрезку, а не тайминги субтитров.
  Gemini разводит предложения паузами, которых короткий формат не терпит, а своей
  ручки скорости у него нет.
- **Непрерывный фон из одного длинного видео** (`continuous_background`, по умолчанию
  выключено): вместо нарезки из множества клипов берётся один отрезок со случайного
  места длинного исходника под длину озвучки и кропается по центру под формат кадра
  (без чёрных полей). Резка, кроп и масштабирование — один вызов FFmpeg: 5-секундный
  фон собирается за 3 с вместо 57 с на MoviePy. Если исходника нужной длины нет или
  FFmpeg упал — фолбэк на штатную склейку. CLI:
  `--continuous-background/--no-continuous-background` —
  `architecture/continuous-background.md`.
- **Фото-вставки из локальной папки** на сильных фразах сценария: моменты выбирает
  LLM (фолбэк — равномерная раскладка), каждое фото показывается 1.5–2.5 сек с
  анимацией появления (`pop`/`slide`/`kenburns`/`random`); выключены по умолчанию
  (`photo_enabled = false`). CLI: `--photo-enabled/--no-photo-enabled`,
  `--photo-dir`, `--photo-amount`, `--photo-size`, `--photo-animation` —
  `architecture/photo-overlays.md`.
- **Капс в субтитрах** (`subtitle_uppercase`, по умолчанию выключено): текст фразы
  поднимается в верхний регистр только при рендере, в TTS уходит как есть.
  CLI: `--subtitle-uppercase/--no-subtitle-uppercase`.
- **Подсветка ключевого слова в субтитрах** (`subtitle_highlight_enabled`, по умолчанию
  выключено; цвет — `subtitle_highlight_color`, по умолчанию `#FFD700`): одно слово на
  фразу выбирается детерминированной эвристикой (цифра > самое длинное слово ≥5 букв
  вне стоп-списка) и рисуется другим цветом через PIL → `ImageClip`. Karaoke-подсветка
  невозможна без пословных таймингов TTS — `architecture/subtitle-highlight.md`.
  CLI: `--subtitle-highlight`, `--subtitle-highlight-color`.
- **CLI: gif-флаги** — `--gif-enabled/--no-gif-enabled`, `--gif-amount`, `--gif-size`,
  `--gif-rating`; раньше gif-оверлеи включались только из WebUI или кодом через
  `VideoParams`.
- **Пресет `playbook` включён по умолчанию** (`config.example.toml`): текст ролика
  строится по модели из `docs/playbook/`, а не по апстримному общему промпту.
- **Выбор хука отдельным шагом** — `hook_candidates = 5` кандидатов, детерминированный
  отсев приветствий и анонсов темы, затем скорер; выбранная строка пиннится в сценарий
  дословно, `hook`/`hook_type` уезжают в состояние задачи —
  `architecture/hook-selection.md`.
- **Провайдер `claude_code`** — генерация текста через локальный `claude -p`
  вместо HTTP-API, на интерактивной подписке; ключ и Base URL не нужны.
  Бинарник ставится в Docker-образ (`ARG INSTALL_CLAUDE_CODE=1`), учётные
  данные монтируются с хоста — `architecture/claude-cli-provider.md`.
- **Пресет промпта сценария по плейбуку** (`script_prompt_preset = "playbook"`,
  по умолчанию выключен): такты, правила хука, правило удержания, приоры
  длительности по платформе и опциональный скелет формата.
- **`docs/playbook/`** — ремесленная часть контекста разложена на пять файлов (хуки,
  сценарий, форматы, тайминги, публикация); в `product/content-factory-context.md` на их
  месте остались заголовки-указатели, нумерация разделов сохранена.
- **GIF-вставки KLIPY** на эмоциональных пиках сценария; выключены по умолчанию
  (`gif_enabled = false`), пайплайн без них не меняется — `architecture/gif-overlays.md`.
