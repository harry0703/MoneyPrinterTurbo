# ADR 0002: пороги photo retrieval задаются измеренной калибровкой

- Статус: принято
- Дата: 2026-08-18

## Контекст

Косинусные значения зависят от embedding-модели, состава базы и языка captions.
Универсальные пороги, выбранные без живых кандидатов, дают ложные accept либо
оставляют систему без пригодных результатов.

## Решение

Веса, границы accept/reject и окно свежести находятся в конфиге. Их выбирают по
выводу `library calibrate`, открывая реальные top-1/top-2 кандидаты для visual
briefs. Текущая калибровка на 466 ассетах:

```text
score = 0.85 × cosine + 0.10 × tag_score − 0.05 × recency_penalty
accept >= 0.68
gray   >= 0.54 и < 0.68
reject < 0.54
recency window = последние 20 задач
```

## Последствия

- Числа нельзя молча менять как «инженерные дефолты» без нового замера.
- Смена embedding-модели или заметное расширение базы требует повторной
  калибровки.
- После первых 20 реальных задач отдельно перепроверяются freshness weight/window:
  при исходном замере история использования была пуста.
